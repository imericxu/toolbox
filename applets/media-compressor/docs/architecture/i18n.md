# Internationalization

Paraglide JS + Inlang message-format. Agents choose and manage keys; `scripts/i18n-check.ts` enforces the rules.

Dates and times: see [dates.md](./dates.md).

## Layout

| Path                     | Purpose                                                    |
| ------------------------ | ---------------------------------------------------------- |
| `messages/{locale}.json` | Flat JSON, one file per locale. Source of truth.           |
| `project.inlang/`        | Inlang settings (locales, plugins).                        |
| `src/paraglide/`         | Generated by `bun run i18n:gen`. Never edit.               |
| `scripts/i18n-check.ts`  | Validator and the scope/role registry (`SCOPES`, `ROLES`). |

Use messages as `import { m } from "#/paraglide/messages"` then `m.app__title()`.

## Key grammar

```
<scope>__<element>__<role>[__<variant>]
```

- Segments separated by `__`. Words inside a segment joined by `_` (`file_picker__drop_zone__hint`).
- Lowercase ASCII `[a-z0-9_]`. 2-4 segments. Each segment 1-4 words. Each word 1-15 chars.
- First segment must be in `SCOPES`. Last segment must be in `ROLES`.
- Keys name purpose, never text. Do not rename a key when copy changes.
- Params are camelCase: `{fileCount}`.

### Scopes

A scope is the feature or domain that owns a string, never a route or file path. A string moving between routes keeps its key. Add feature scopes (e.g. `compression`, `file_picker`) as features appear.

| Scope    | Meaning                                  |
| -------- | ---------------------------------------- |
| `app`    | App-wide shell: title, navigation.       |
| `common` | Generic strings shared by several areas. |
| `error`  | Error messages not tied to one feature.  |

### Roles

The role encodes the grammatical sense, so identical English words stay distinct.

| Role          | Sense                                          |
| ------------- | ---------------------------------------------- |
| `action`      | Verb/imperative: buttons, menu items ("Open"). |
| `status`      | Adjective/state ("Open", "Done").              |
| `label`       | Noun: field or section label.                  |
| `title`       | Heading or dialog title.                       |
| `description` | Longer explanatory text.                       |
| `placeholder` | Input placeholder.                             |
| `aria`        | Screen-reader-only text.                       |
| `error`       | Error or validation message.                   |
| `hint`        | Helper or instructional text.                  |

### Examples

| Key                            | Verdict | Why                                                      |
| ------------------------------ | ------- | -------------------------------------------------------- |
| `app__title`                   | good    |                                                          |
| `app__drop_zone__drop_hint`    | bad     | `drop_hint` is not a role; use `app__drop_zone__hint`    |
| `file__open__action`           | bad     | `file` is not a scope until added                        |
| `common__open__action`         | good    | verb "Open"                                              |
| `common__open__status`         | good    | adjective "Open"                                         |
| `grumpy_keys_swim`             | bad     | random, no segments                                      |
| `Home__Title`                  | bad     | uppercase                                                |
| `common__file__label__one`     | bad     | variant suffix; use plural syntax                        |
| `app_title`                    | bad     | single underscore between segments                       |

Never reuse a key across senses, even when today's English text is identical.

## Variants: one key, Inlang syntax

Do not create `__one`/`__other`, `__singular`/`__plural`, or per-state keys. The validator rejects them.
Verified against `plugin-message-format@4` and `@inlang/paraglide-js` 2.25.

Plural:

```json
"common__file_count__label": [
  {
    "declarations": ["input count", "local countPlural = count: plural"],
    "selectors": ["countPlural"],
    "match": {
      "countPlural=one": "{count} file selected",
      "countPlural=*": "{count} files selected"
    }
  }
]
```

Closed-set selector (list every case, no `*` fallback; Paraglide generates a union param):

```json
"common__job__status": [
  {
    "declarations": ["input status"],
    "selectors": ["status"],
    "match": {
      "status=idle": "Idle",
      "status=running": "Running",
      "status=done": "Done"
    }
  }
]
```

Generated param type is `status: "done" | "idle" | "running"`. Adding a `*` fallback widens it to `NonNullable<unknown>`, so only use `*` for genuinely open sets.

Markup: `"common__terms__hint": "Read the {#link}terms{/link}."`. Use `m.common__terms__hint.parts()` to render. Never concatenate message fragments.

Formatting: `{count :number}`, `{when :datetime}` inside the text. For dates prefer pre-formatted strings, see [dates.md](./dates.md).

## Agent procedure

1. Search `messages/en.json` for an existing key with the same sense. Reuse it.
2. Pick scope (feature/domain, never a route or file path), element (UI thing), role (sense). Prefer existing registry entries.
3. If no scope or role fits, add it to `SCOPES`/`ROLES` in `scripts/i18n-check.ts` AND the tables above, in the same change, with a one-line description. Only add a role when no existing role fits the sense.
4. Write the key in `messages/en.json`, using variant syntax where needed.
5. Run `bun run i18n:check` (add `-- --fix` to sort keys), then `bun run i18n:gen`.
6. Done when both pass.

## Checks enforced by `i18n:check`

Key grammar, word counts and lengths, allowed scope and role, banned variant suffixes, sorted keys, identical key sets across locales. It also runs as part of `bun run lint`.

## Adding a locale

1. Add the locale to `locales` in `project.inlang/settings.json`.
2. Create `messages/{locale}.json` with every key from `en.json`.
3. Run `bun run i18n:check` then `bun run i18n:gen`.
